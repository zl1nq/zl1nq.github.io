三、五大核心概念

RabbitMQ 的消息流转模型涉及 5 个核心角色，理解它们是后续所有操作的基础：

概念速查表

角色 英文 职责说明 类比
生产者 Publisher 发送消息的一方：业务服务把消息投递出去 快递寄件人
消费者 Consumer 消费消息的一方：从队列里取消息处理业务 快递收件人
队列 Queue 存储消息的容器。生产者投递的消息暂存在这里，等消费者处理 快递驿站
交换机 Exchange 负责消息路由：生产者不直接投递到队列，而是发给交换机，由它决定投递到哪个/哪些队列 快递分拣中心
虚拟主机 Virtual Host（vhost） 逻辑隔离单位。每个 vhost 有独立的 exchange、queue、权限，互不干扰 不同的城市快递系统

💡 关键认知：

  • 交换机不存储消息，只做路由。队列没绑定？→ 消息直接丢
  • 生产者 → 交换机 → 队列 → 消费者，消息流转是这个顺序

四、控制台实战：收发消息四步走

下面通过控制台一步步演示消息从「发送」到「到达队列」的全过程，帮助理解上面的概念。

第 1 步：发送消息（没有队列时消息会丢）

  1. 打开 Exchanges 选项卡，看到已经存在很多预设的交换机
  2. 点击任意交换机（比如 amq.fanout）进入详情页
  3. 找到 Publish message 表单，填入内容点击发送

⚠️ 结果：消息丢了！
为什么？ 交换机没有存储能力，又没有任何队列和它绑定，消息无处可去就直接丢了。

✅ 结论：仅仅发消息是不够的，必须先有队列，还要把队列绑定到交换机上。

第 2 步：创建两个队列

为什么？因为队列和交换机之间还没有绑定关系。

第 3 步：绑定交换机与队列 ⭐

绑定（Binding）是 RabbitMQ 路由的核心纽带：只有绑定了，交换机才知道消息该发给哪个队列。

操作步骤：

  1. 回到 Exchanges 选项卡，点击 amq.fanout 进入详情
  2. 找到 Bindings 菜单
  3. 表单中填写队列名 hello.queue1，点击 Bind 绑定
  4. 同样操作绑定 hello.queue2

✅ 结果：消息同时到达了 hello.queue1 和 hello.queue2 两个队列！

此时如果有程序连接 MQ，监听 hello.queue1 或 hello.queue2，就能消费到消息了。

四步流程复盘

步骤 操作 学到的知识点
① 直接发消息 交换机不存消息，没绑定就丢
② 创建队列 队列是存储消息的容器
③ 绑定交换机-队列 Binding 是路由纽带，必须建立
④ 再发消息 消息成功路由到队列

2. 数据隔离原理 ⭐

RabbitMQ 通过「用户 + Virtual Host」的组合实现多租户数据隔离：

隔离手段 说明
Virtual Host 每个 vhost 有独立的交换机、队列、绑定，名字相同也互不影响
用户权限 给用户分配只能访问某个 vhost 的权限，不能操作其他 vhost

🏢 类比：

  • Virtual Host = 不同的小区
  • 交换机/队列 = 小区里的快递柜
  • 用户 = 住户，只能进自己小区（vhost）取快递

这样多个团队共用一套 RabbitMQ 集群，数据完全隔离，谁也碰不到谁的数据。
