一、类定义与构造器

核心要点：Python 使用 class 关键字定义类，__init__ 作为构造器，self 等价于其他语言的 this。

1. init 构造器

  • __init__ 是 Python 的魔法方法，代替构造方法
  • self 必须显式写在参数第一位（调用时不需要传，Python 自动传入）
  • 属性不用提前声明，在 __init__ 里直接 self.xxx = ... 就创建了

💡 对比 Java：

  • Java 需要先声明字段，再写构造器赋值
  • Python self.xxx 赋值即可创建，更简洁

二、实例化与属性访问

⭐ Python 所有属性默认 public，想私有化加 __ 前缀（名称修饰）。

1. 实例化

不需要 new 关键字，直接 类名(参数) 即可。

2. 访问修饰对比

修饰方式 写法 访问权限
公开 self.name 外部直接访问 obj.name
私有（名称修饰） self.__name 外部不能直接访问，实际被改名为 _类名__name
保护（约定） self._name 单下划线只是约定，实际上仍可直接访问

⚠️ 注意：Python 的 __ 双下划线不是真正的私有，只是名称修饰（Name Mangling），通过 obj._类名__属性 仍可访问。主要用于防止子类意外覆盖，不是安全机制。

三、私有属性与封装（@property）

1. 传统 Getter/Setter 写法

这种写法能用，但不够 Pythonic。

2. Pythonic 方式：@property 装饰器 ⭐

@property 可以把方法「伪装」成属性，调用时不用写括号，更优雅。

使用方式

✅ @property 优势：

  • 调用方无需感知是方法，像属性一样用 obj.balance
  • 向后兼容：从公开属性改为 property，调用方代码不用改
  • Setter 中可以加校验逻辑，保证数据有效性

3. 核心区别

@classmethod：能访问/修改类变量，能被子类继承重写。常用于工厂模式创建对象。

@staticmethod：工具函数，和类关联但不需要类/实例信息。本质上就是放在类命名空间里的普通函数。

六、继承（单继承 + 多重继承）

1. 单继承 + 方法重写

💡 super() 用法：

  • super() 返回父类代理对象，调用父类方法
  • 常用于 __init__ 中调用父类构造器，避免重复代码

2. 多重继承

Python 支持一个类同时继承多个父类。

⚠️ 多重继承注意事项：

  • 多个父类有同名方法时，按 MRO（方法解析顺序） 从左到右查找
  • 用 类名.__mro__ 查看继承链
  • 过度使用多重继承会导致代码复杂，优先考虑组合模式

🦆 “If it walks like a duck and it quacks like a duck, then it must be a duck.”

只要有 quack 方法，我就认为你是鸭子。不关心继承关系，只关心有没有对应的行为。🤯

2. 底层逻辑

Python 解释器遇到 animal.quack() 时，逻辑非常简单：

  1. 去 animal 对象的内部字典（__dict__）里找，有没有叫 quack 的键？
  2. 找到了，就执行。
  3. 没找到，直接抛 AttributeError。

根本不关心 animal 到底是 Duck、Robot 还是 Dog。这就是动态类型语言的运行时检查。

3. 优缺点

优点 缺点
极度灵活：代码解耦，不需要庞大的继承树和接口 缺乏 IDE 智能提示：参数无类型，IDE 难自动补全
代码量少：省去大量样板代码 运行时才报错：Java 编译期报错，Python 可能跑 10 分钟才出错

💡 Python 3.5+ 解决方案：用**类型注解（Type Hints）**弥补，配合 mypy 做静态检查。
