Java并发编程01

理论知识

进程 vs 线程

1. 进程

  • 运行一次 .java 程序，启动 JVM，操作系统会创建 1 个独立进程。
  • 进程是操作系统资源分配最小单位：独立内存、文件句柄、CPU 配额；
  • 进程之间完全隔离，不能直接共享内存；
  • 任务管理器看到的 java.exe 就是一个 Java 进程。

2. 线程

  • 进程内部的执行单元，CPU 调度最小单位。
  • 一个进程至少自带主线程 main；
  • 同进程内所有线程共享进程堆内存，可以互相访问对象，所以才有并发安全问题；
  • 每个线程独有：程序计数器 PC、虚拟机栈、本地方法栈。

简单理解：

  • 进程 = 独立容器；线程 = 容器里干活的工人。

Java 程序启动底层流程

  1. 双击 / 命令执行 java
  2. OS 创建一个 JVM 进程，分配一块独立内存空间
  3. JVM 内部自动创建主线程 main，执行 main() 方法
  4. 代码里 new Thread().start()：
    • JVM 调用底层操作系统 API（Linux pthread / Windows CreateThread）
    • OS 在当前 JVM 进程内部，新建一条内核线程
    • 分配独立栈内存，加入 CPU 调度队列
  5. CPU 轮转分配时间片，多条线程交替执行，形成 “并发”

JVM 内存和线程的关系

线程私有（每条线程自己独一份）

  • 虚拟机栈：存局部变量、方法调用栈帧，线程销毁栈直接释放
  • 本地方法栈：给 native 方法（C/C++）用
  • 程序计数器 PC：记录当前执行到哪一行代码，切换线程时保存现场

进程共享（所有线程共用）

  • 堆 Heap：new 出来的对象全部放这里，多线程争抢 → 并发安全问题
  • 方法区 / 元空间：类信息、静态变量、常量池

并发根源： 堆共享，多线程同时读写同一个对象，出现可见性、原子性、有序性问题。

CPU、内核线程、Java 线程关系

  • CPU 核心：真正执行指令的硬件，多核可以真正并行；单核只能并发切换。
  • 内核线程 LWP：操作系统底层线程，CPU 调度对象。
  • Java 线程模型：一对一模型
    • 1 个 Thread 对象 ↔ 1 个操作系统内核线程
    • 优点：利用多核、调度由 OS 优化；
    • 缺点：创建线程有内核开销，大量线程会占用内存、切换耗性能。

线程切换开销

线程从 CPU 切走、再切回来叫上下文切换：

  1. 保存当前线程 PC、栈、寄存器数据
  2. 加载另一条线程现场

大量切换会占用 CPU 资源，这就是线程池存在的意义 —— 复用线程，减少创建销毁切换开销。

极简面试背诵版

  • 运行 Java 程序生成一个 JVM 进程，进程是资源分配单位；
  • 进程自带 main 主线程，start() 创建新线程，线程是 CPU 调度单位；
  • 同进程线程共享堆、元空间；栈、PC 计数器线程私有；
  • Java 线程采用操作系统一对一内核线程模型；
  • 多线程共享堆内存读写数据，引发并发三大问题。

守护线程的核心特性

  • 生命周期依附用户线程
    守护线程存在的意义是服务用户线程；无用户线程则自动销毁。
  • 线程继承属性
    线程的 daemon 属性会继承父线程：
    在守护线程内创建新线程，新线程默认也是守护线程；
    在普通主线程创建，默认用户线程。
  • JVM 退出时不会等待守护线程收尾
    守护线程被强制终止，不会抛异常、不会执行完剩余逻辑，不要在守护线程执行 IO、文件保存、事务等重要操作，会丢失数据。
  • 不能用于执行业务任务
    只适合后台辅助任务：心跳检测、日志定时刷新、GC、缓存过期清理等

线程的中断

1、三个核心方法区分

  • void thread.interrupt()
    给目标线程打上中断标记，不是立刻停止线程，只是修改一个布尔标识。
  • boolean thread.isInterrupted()
    判断当前线程是否带有中断标记，不会清除标记。
  • static boolean Thread.interrupted()
    判断当前线程中断标记，调用后自动清除标记（静态方法）。

2、核心概念：中断只是 “通知”，不是强制杀死

Java 没有任何 API 能直接强行终止线程，中断是协作式机制：
A 线程调用 t.interrupt() → 给 t 线程设中断标志；
t 线程内部需要主动检测中断标记，自己决定是否退出、怎么退出
两种场景的中断表现
场景 1：线程处于阻塞状态（sleep/wait/join）
线程在sleep()、wait()、join()阻塞时，如果收到中断标记，会立刻抛出 InterruptedException，并自动清除中断标记。

3、isInterrupted () 和 interrupted () 关键区别

4、synchronized 等待锁时无法被中断

调用 interrupt() 不会唤醒正在等待 synchronized 锁的线程，只能等抢到锁之后，下一次检测中断标记才生效；
而 ReentrantLock.lockInterruptibly() 等待锁时可以响应中断，抛出异常，这是 Lock 的优势之一。

5、利用中断来优雅退出线程

原理：线程在阻塞时被中断，会立刻抛出InterruptedException。

就比如sleep()，如果在线程睡眠时被中断，会立刻抛出InterruptedException，线程会退出。

线程 A 执行 Thread.sleep(长时间)，进入阻塞状态；
执行 A.interrupt()，给 A 打上中断标记；
JVM 检测到该线程正在 sleep 阻塞，立即唤醒线程，不会等到 sleep 时间结束；
自动清除中断标记，抛出 InterruptedException；
代码进入 catch 块，处理相应逻辑。

6、面试极简总结

interrupt() 仅设置中断标识，不强制终止线程；
阻塞 (sleep/wait/join) 时中断会抛InterruptedException并清除标记；
运行中线程需要主动isInterrupted()检测标记，自行退出；
interrupted()静态方法查询并清除标记，isInterrupted()只查询；
synchronized 等待锁不可中断，lockInterruptibly 支持等待锁时中断。
