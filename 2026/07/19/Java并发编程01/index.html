Java并发编程01

理论知识

进程 vs 线程

1. 进程

  • 运行一次 .java 程序，启动 JVM，操作系统会创建 1 个独立进程。
  • 进程是操作系统资源分配最小单位：独立内存、文件句柄、CPU 配额；
  • 进程之间完全隔离，不能直接共享内存；
  • 任务管理器看到的 java.exe 就是一个 Java 进程。

2. 线程

  • 进程内部的执行单元，CPU 调度最小单位。
  • 一个进程至少自带主线程 main；
  • 同进程内所有线程共享进程堆内存，可以互相访问对象，所以才有并发安全问题；
  • 每个线程独有：程序计数器 PC、虚拟机栈、本地方法栈。

简单理解：

  • 进程 = 独立容器；线程 = 容器里干活的工人。

Java 程序启动底层流程

  1. 双击 / 命令执行 java
  2. OS 创建一个 JVM 进程，分配一块独立内存空间
  3. JVM 内部自动创建主线程 main，执行 main() 方法
  4. 代码里 new Thread().start()：
    • JVM 调用底层操作系统 API（Linux pthread / Windows CreateThread）
    • OS 在当前 JVM 进程内部，新建一条内核线程
    • 分配独立栈内存，加入 CPU 调度队列
  5. CPU 轮转分配时间片，多条线程交替执行，形成 “并发”

JVM 内存和线程的关系

线程私有（每条线程自己独一份）

  • 虚拟机栈：存局部变量、方法调用栈帧，线程销毁栈直接释放
  • 本地方法栈：给 native 方法（C/C++）用
  • 程序计数器 PC：记录当前执行到哪一行代码，切换线程时保存现场

进程共享（所有线程共用）

  • 堆 Heap：new 出来的对象全部放这里，多线程争抢 → 并发安全问题
  • 方法区 / 元空间：类信息、静态变量、常量池

并发根源： 堆共享，多线程同时读写同一个对象，出现可见性、原子性、有序性问题。

CPU、内核线程、Java 线程关系

  • CPU 核心：真正执行指令的硬件，多核可以真正并行；单核只能并发切换。
  • 内核线程 LWP：操作系统底层线程，CPU 调度对象。
  • Java 线程模型：一对一模型
    • 1 个 Thread 对象 ↔ 1 个操作系统内核线程
    • 优点：利用多核、调度由 OS 优化；
    • 缺点：创建线程有内核开销，大量线程会占用内存、切换耗性能。

线程切换开销（为什么不随便开上千线程）

线程从 CPU 切走、再切回来叫上下文切换：

  1. 保存当前线程 PC、栈、寄存器数据
  2. 加载另一条线程现场

大量切换会占用 CPU 资源，这就是线程池存在的意义 —— 复用线程，减少创建销毁切换开销。

极简面试背诵版

  • 运行 Java 程序生成一个 JVM 进程，进程是资源分配单位；
  • 进程自带 main 主线程，start() 创建新线程，线程是 CPU 调度单位；
  • 同进程线程共享堆、元空间；栈、PC 计数器线程私有；
  • Java 线程采用操作系统一对一内核线程模型；
  • 多线程共享堆内存读写数据，引发并发三大问题。

多线程实现方法

1、继承 Thread 类

2、实现 Runnable 接口

3、实现 Callable 接口和 Future 接口

这种方法可以获取子线程的返回值🤩

  • get() 会阻塞主线程：如果子线程没执行完，主线程卡在 get() 不动，因此不要在主线程频繁无超时 get。
  • 同一个 FutureTask 只能执行一次：多个 Thread 传入同一个 FutureTask，只会执行一次 call()，后续线程直接拿结果。
  • 任务异常处理：任务内部抛出异常，会被封装进 ExecutionException，在 get() 时抛出，而不是启动时。
  • 适用场景：需要线程返回结果、需要捕获任务异常、需要控制任务取消。

Synchronized 关键字

1、基本概念

  • synchronized 是 Java 内置的互斥锁，也叫对象锁或内置锁。
  • 保证原子性：同一时刻只有一个线程能执行被 synchronized 保护的代码。
  • 保证可见性：线程解锁时，会将共享变量刷新到主内存；加锁时，会从主内存重新读取。
  • 保证有序性：通过互斥执行，消除指令重排序带来的问题。

核心作用：解决多线程并发访问共享资源时的线程安全问题。

2、三种使用方式

方式一：修饰实例方法

方式二：修饰静态方法

方式三：修饰代码块

3、锁的类型对比

锁类型 锁对象 锁住的范围
实例方法锁 this 当前对象的所有实例方法
静态方法锁 类名.class 当前类的所有静态方法
代码块锁 指定对象 只有代码块内的代码

4、核心特性

  • 可重入性：同一个线程可以多次获得同一把锁，不会自己锁死自己。
  • 排他性：同一时刻只能有一个线程持有锁（悲观锁）。
  • 自动释放：线程执行完同步代码或发生异常时，会自动释放锁。
  • 锁的是对象而非方法：关键看锁的是哪个对象。

5、底层原理

对象头（Object Header）

Java 对象在内存中分为三部分：

  1. 对象头：存储对象的元数据，包括 Mark Word、类指针等。
  2. 实例数据：对象的成员变量。
  3. 对齐填充：保证对象大小是 8 字节的倍数。

Mark Word 是 synchronized 实现锁的关键，它存储了锁的状态信息：

锁状态 Mark Word 内容
无锁 对象哈希码 + 分代年龄
偏向锁 偏向线程 ID + Epoch + 分代年龄
轻量级锁 指向栈中锁记录的指针
重量级锁 指向 Monitor 对象的指针

Monitor 对象

当锁升级为重量级锁时，JVM 会为对象分配一个 Monitor（管程）对象：

  • Entry Set：等待获取锁的线程队列。
  • Owner：当前持有锁的线程。
  • Wait Set：调用 wait() 等待的线程队列。

6、锁升级过程

偏向锁：

  • 适用于单线程重复获取锁的场景。
  • 第一次获取锁时，记录线程 ID，后续同一线程直接获取，无需 CAS 操作。

轻量级锁：

  • 当有多个线程交替获取锁时，偏向锁升级为轻量级锁。
  • 使用 CAS 操作尝试获取锁，失败则自旋等待。

重量级锁：

  • 当自旋次数过多或线程阻塞时，升级为重量级锁。
  • 涉及操作系统内核态切换，性能开销较大。

7、常见误区

  • 锁的是对象不是代码：两个方法如果锁的不是同一个对象，依然存在并发问题。
  • 字符串常量池陷阱：synchronized ("abc") 可能导致不同代码段意外地互相阻塞。
  • 死锁：两个线程互相持有对方需要的锁，导致永久阻塞。

8、极简面试背诵版

  • synchronized 是 Java 内置互斥锁，保证原子性、可见性、有序性；
  • 三种用法：修饰实例方法（锁 this）、静态方法（锁 Class）、代码块（锁指定对象）；
  • 锁可重入、自动释放、排他性；
  • 底层依赖对象头 Mark Word 和 Monitor；
  • 锁升级过程：无锁→偏向锁→轻量级锁→重量级锁。
