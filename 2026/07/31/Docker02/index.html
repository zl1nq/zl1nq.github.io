2. 默认网络：bridge 网桥

默认情况下，所有启动的容器都会以 bridge 驱动方式，连接到 Docker 预置的一个虚拟网桥（默认名为 bridge，对应宿主机上的 docker0 网卡）。

默认网络特性 说明
驱动类型 bridge（桥接模式，Docker 最常用的默认模式）
互通性 同一个默认 bridge 网络下的容器之间互 ping 可以 ping 通
识别方式 容器之间只能通过 IP 互相访问，不能通过容器名

⚠️ 关键提醒：默认 bridge 网络下，Docker 不支持通过容器名做 DNS 解析，只能通过 IP 通信。

二、默认网络的四大痛点

默认网络虽然能用，但在实际开发中存在以下问题：

痛点 1：IP 不固定，写死会失效 ❌

容器的 IP 是动态分配的虚拟 IP，不与某一个容器永久绑定：

  • 容器重启 → IP 可能变化
  • 容器删除重建 → IP 一定变化

开发时如果把 MySQL 连接配置写死为某个 IP，部署时 MySQL 容器 IP 一变，连接直接失败。

痛点 2：只能用 IP，不能用容器名通信

默认 bridge 网络下，两个容器想通信必须知道对方的 IP，不能写 mysql、redis 这样的容器名——因为默认网络没有内置 DNS。

痛点 3：所有容器在同一网段，缺少隔离

所有容器共用一个 bridge 网桥，任何两个容器默认都能互访，缺少业务层面的网络隔离。
比如 A 项目的容器和 B 项目的容器可以随便连，不安全。

痛点 4：不支持容器别名（–alias）

默认网络下连接时不能使用 --alias 参数给容器起别名，网络标识不灵活。

🎯 结论：生产/开发环境强烈推荐使用自定义网络，上面四个问题一次性解决。

三、自定义网络（推荐方案）

1. 什么是自定义网络

用户自己用 docker network create 创建的网络，本质上是新建一个独立的虚拟网桥，所有加入这个网络的容器在逻辑上处于同一个「局域网」中。

2. 自定义网络的四大优势 ⭐

能力 说明
✅ DNS 解析 同一个自定义网络下，容器可以直接用容器名互相通信
✅ 网络隔离 不同自定义网络的容器默认不能互访，天然多项目隔离
✅ IP 稳定（相对） 同一次运行中 IP 稳定；即使 IP 变了也不怕，因为用容器名通信
✅ 别名支持 连接时可通过 --alias 给容器起多个别名，访问更灵活

3. 自定义网络的 DNS 解析原理

🧠 核心机制：自定义的 bridge 网络内置了 DNS 服务。

容器 A ping mysql → 自定义网络的 DNS 服务解析到 mysql 容器的 IP → 建立连接。

所以不用管 IP 是什么，只要容器名/别名不变，连接永远不失效。

四、网络操作命令速查

1. 基础命令

命令 作用
docker network ls 列出所有网络（含默认的 bridge/none/host）
docker network create <name> 创建自定义网络（默认 bridge 驱动）
docker network rm <name> 删除指定网络
docker network prune 删除所有未使用的网络

2. 容器连接命令

命令 作用
docker network connect <net> <容器> 把已运行的容器加入某网络
docker network connect --alias <别名> <net> <容器> 加入网络同时指定 DNS 别名
docker network disconnect <net> <容器> 把容器从某网络断开
docker run --network <net> ... 新建容器时直接指定网络，不入默认网络

3. 查看详情

命令 作用
docker network inspect <net> 查看某网络详情（含已连接的容器、IP 分配情况）
docker inspect <容器> 查看容器详情，包含它所属的所有网络和 IP

六、两种方式加入网络对比

实际使用中，容器加入自定义网络有两种路径，效果略有差别：

对比项 run 时 --network demo 运行后 network connect
默认 bridge ❌ 不加入，只在 demo 中 ✅ 同时在 bridge + demo（双网络）
是否要重启 启动时直接生效 无需重启，立即生效
适用场景 新建容器（推荐） 已运行的容器需要临时加入
网络隔离 严格隔离（和默认网络不通） 容器可同时和两个网络的容器互通
指定别名方式 docker run --network-alias <别名> docker network connect --alias <别名>

🧐 思考：为什么 connect 会双网卡？
因为 connect 的语义是「加入一个新网络」，而不是「切换」——不破坏原有网络连接。如果确实只想要自定义网络，就必须在 run 时指定。
