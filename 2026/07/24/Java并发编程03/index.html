Lock vs synchronized

特性 synchronized Lock(ReentrantLock)
类型 隐式锁，自动释放 显式锁，手动 lock/unlock
可中断 不可中断 lockInterruptibly()支持中断
尝试获取 不支持，拿不到一直阻塞 tryLock()非阻塞、限时等待
公平锁 非公平 支持公平 / 非公平构造选择
条件队列 1 个 wait/notify 多个 Condition，精准唤醒
重入 支持可重入 ReentrantLock 支持可重入
锁状态 无法判断是否持有锁 isLocked()、isHeldByCurrentThread()
底层 对象头监视器锁（Mark Word） AQS(AbstractQueuedSynchronizer)

简单结论：简单同步用 synchronized；需要灵活控制（限时、中断、多条件、公平锁）选 Lock。

实现类

ReentrantLock 可重入锁

构造方法

  • 公平锁：线程按照请求顺序获取锁（先来后到）
  • 非公平锁：线程抢占式获取锁（可能插队）

可重入特性：同一线程多次 lock 不会阻塞，每次 lock 必须对应一次 unlock。

常用 API

ReentrantReadWriteLock 读写锁

读写锁（ReadWriteLock）是一种特殊的锁，用于在多线程环境下安全地访问共享资源。它由一个读锁和一个写锁组成，分别用于读取共享资源和写入共享资源。

支持可重入锁，即同一线程可以 lock 多次，每次 lock 必须对应一次 unlock。

  • 读锁：多个线程可以同时获取读锁，读取共享资源，不会阻塞其他线程的读取操作。
  • 写锁：只有一个线程可以获取写锁，写入共享资源，会阻塞其他线程的读取和写入操作。

读写锁的升降级

核心概念：

操作 方向 是否允许 说明
锁降级 写锁 → 读锁 ✅ 允许 先获取写锁，再获取读锁，然后释放写锁
锁升级 读锁 → 写锁 ❌ 不允许 可能导致死锁
1. 锁降级

什么是锁降级？

写锁降级为读锁：持有写锁时获取读锁，然后释放写锁，最终只持有读锁。

为什么需要锁降级？

保证数据一致性的同时提高并发性：

  • 写锁保证修改的原子性
  • 降级为读锁后，其他线程可以并发读取
  • 当前线程继续持有读锁，确保能读到自己的修改

锁降级流程：

  1. 获取写锁
  2. 获取读锁
  3. 释放写锁（此时持有读锁，降级完成）
  4. 业务读完后释放读锁
2. 锁升级

什么是锁升级？

读锁升级为写锁：持有读锁时尝试获取写锁。

⚠️ 不可以直接升级，因为读锁和写锁是互斥的，不能同时持有！

需要先释放读锁，才能升级为写锁。

StampedLock

StampedLock 不是 Lock 接口的实现类，它是一个独立的锁机制，与 ReentrantLock、ReentrantReadWriteLock 属于不同的继承体系。

⚠️ StampedLock 不支持重入，同一线程重复获取锁会导致死锁！

基本使用

原理

StampedLock 通过一个 64 位 long 类型的变量 state（戳记）来同时表示锁状态和版本号，实现高性能的读写锁。

1. 核心状态变量 state

内部用一个 long state 变量 同时记录两件事：

  1. 锁状态（写锁 / 悲观读锁）
  2. 版本戳（每次写操作发生，版本号就递增）

64 位被拆成三部分：

  • 低 7 位（bit0~bit6）：悲观读计数器，记录当前持有悲观读锁的线程数
  • 第 7 位（WBIT）：写锁标记位，1 代表独占写锁被占用，0 代表无写锁
  • 高位（bit8~bit63）：版本号，数据每完成一次写入就 +1，专门给乐观读做有效性校验

所有加锁操作都会返回一个 stamp（票据），解锁时凭票据操作。

2. 三种模式底层逻辑

① 乐观读 tryOptimisticRead()
  • 不上锁！
  • 直接把当前 state 作为 stamp 返回。
  • 读取共享数据后，调用 validate(stamp)，判断此刻 state 和拿到的 stamp 是否相等：
    • 相等：期间没有写操作，数据有效
    • 不等：有线程执行过写锁，数据被篡改，版本号变更 → 要升级悲观读重拿数据

本质：版本号校验，无锁并发

② 悲观读 readLock()（共享）
  • 多个线程可以同时拿到悲观读；
  • 只要有人持有悲观读，写锁就抢不到。
  • 只改动低 7 位读计数：加锁 +1，解锁 -1；
  • 写标记、版本号全程不变 → 单纯的悲观读增减，不会让乐观读校验失败。
③ 写锁 writeLock()（独占）

排他模式：不能和悲观读、其他写锁共存。

  • 一旦写锁成功获取，state 的版本号 +1 → 所有之前乐观读拿到的 stamp 全部 validate 失败。
  • 加写锁时：读计数必须为 0 才能抢锁成功；成功后把第 7 位置 1（标记写锁占用），版本号暂时不变。
  • 释放写锁时：把第 7 位清 0，同时向高位进位让版本号 +1；
    • 这是乐观读能感知数据修改的核心：只要完成一次写入，版本号就上涨，所有旧的乐观读 stamp 都会校验失败。

3. 关键规则

  1. 写操作 = 版本号自增：这是乐观读能感知修改的根本。
  2. 不支持可重入：没有记录持有线程、重入次数；同一个线程重复加锁直接阻塞死锁。
  3. 支持锁尝试转换：悲观读 ↔ 写锁之间可以尝试转换，不用先解锁再加锁。

4. 和读写锁最本质区别

  • ReentrantReadWriteLock：靠 AQS 队列阻塞线程；大量读持续持有，写线程一直等（写饥饿）
  • StampedLock：乐观读不加锁，写线程随时能抢到锁，缓解写饥饿

5. 一句话总结原理

StampedLock 通过一个自带版本号的 state：写操作会递增版本；乐观读拿到版本号无锁读数据，读完校验版本有没有变化；同时提供悲观读、写锁两种阻塞模式。
