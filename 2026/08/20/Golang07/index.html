接口基本概念

⭐ 接口（interface）定义了一组方法签名，不包含实现。任何类型只要实现了这些方法，就满足该接口。

🧠 接口是 Go 实现多态的唯一方式。结构体嵌入是静态的（无多态），接口方法调用是动态分发的。

隐式实现（鸭子类型）

⭐ Go 接口是隐式实现的：无需 implements 关键字声明，只要类型实现了接口要求的所有方法，就自动满足该接口。

💡 这种”走路像鸭子、叫起来像鸭子，那它就是鸭子”的思想称为鸭子类型（Duck Typing）。

空接口

⭐ 空接口 interface{} 没有任何方法，因此所有类型都满足空接口，类似 Java 的 Object。

💡 Go 1.18+ 引入了 any 作为 interface{} 的别名，推荐使用 any。

接口组合

⭐ 接口可以组合其他接口，形成更大的接口。Go 的接口组合与结构体嵌入理念一致。

🧠 这正是 Go 标准库 io.ReadWriter 的设计方式。Go 标准库大量使用小接口组合，鼓励接口越小越好。

值接收者 vs 指针接收者与接口

⚠️ 这是一个高频陷阱：接收者类型决定了哪些值可以赋值给接口变量。

接收者类型 值可以赋值给接口？ 指针可以赋值给接口？
值接收者 func (d Dog) ✅ ✅
指针接收者 func (d *Dog) ❌ ✅

🧠 原因：值接收者方法集包含在指针接收者的方法集中（指针可以解引用为值），但反之不成立。

3. 隐式 vs 显式的取舍

维度 Java（显式 implements） Go（隐式实现）
优点 编译期明确知道实现了哪些接口 最大的解耦：接口和类型互不依赖
优点 IDE 可快速查找接口的实现类 可以为第三方库的类型定义接口
缺点 接口和类型耦合 不易看出类型实现了哪些接口
缺点 无法为已有类型适配新接口 不小心实现了同名方法会”意外满足”接口

🧠 Go 隐式实现的独特价值：你可以为别人的类型定义接口。比如你引入了一个第三方库的 HttpClient，可以在自己的代码中定义一个 Doer 接口，只要 HttpClient 的方法签名匹配，它就自动满足。这在 Java 中需要适配器模式才能实现。

4. 易错点提醒

❌ Go 接口不能有字段，只能有方法签名。不能像 Java 那样在接口中定义常量。

❌ 接口变量是** nil 时调用方法会 panic**（nil 接口没有底层类型）。

❌ 指针接收者方法实现的接口，值类型不能赋值给接口变量，必须用 &Dog{} 赋值。

❌ 空接口 any 虽然能接收任意类型，但使用前必须类型断言恢复具体类型，否则无法访问具体类型的方法和字段。

❌ Go 接口没有默认方法（Java 8 的 default），如果多个类型有公共逻辑，需用组合或函数封装复用。
