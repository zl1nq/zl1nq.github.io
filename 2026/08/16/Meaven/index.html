1. Maven 简介

1.1 什么是 Maven

⭐ Maven 是一个项目管理工具，可以帮助我们自动化构建项目、管理依赖、发布项目。

1.2 为什么使用 Maven

优势 说明
依赖管理 在 POM 文件中声明所需依赖，Maven 自动下载该 jar 包及其所有传递依赖，统一管理版本，避免冲突
构建管理 提供标准的编译、测试、打包流程，一行命令完成整个构建过程，无需手动操作
统一规范 提供标准的项目目录结构和构建流程，团队协作更高效

1.3 核心概念与工作原理

🧠 Maven 的核心是项目对象模型（Project Object Model，POM），它是一个 XML 文件（pom.xml），定义了项目的配置、依赖、插件以及构建过程。

工作原理：

Maven 读取 pom.xml 后，根据文件中定义的规则下载依赖包，然后编译源代码，最终打包成可执行的 jar/war 包。整个过程中，编译、打包、测试等步骤都由 Maven 插件完成，只需在 pom.xml 中配置即可。

1.4 Maven 仓库

⭐ 仓库就是存放 jar 包的地方，按作用范围分为三种：

仓库类型 说明 是否必须
本地仓库 自己电脑上的目录，默认在 ${user.home}/.m2/repository ✅
远程仓库（私服） 公司内部搭建的仓库，用于统一依赖管理和私有 jar 包共享 ❌ 可选
中央仓库 Maven 官方提供的公共仓库，地址：https://repo.maven.apache.org/maven2 ✅ 内置

💡 查找顺序：本地仓库 → 远程仓库（私服）→ 中央仓库。如果配置了远程仓库，Maven 会先从私服下载，找不到再去中央仓库。

以下是一个 POM 文件示例，包含核心配置项：

POM 核心标签说明：

标签 说明
<groupId> 公司或组织的唯一标识（如 com.companyname.project-group）
<artifactId> 项目的唯一 ID，一个 groupId 下通过它区分不同项目
<version> 版本号
<properties> 属性变量，可被其他地方以 ${变量名} 引用
<dependencies> 实际引入的依赖
<dependencyManagement> 仅声明依赖版本，不实际引入，子模块继承时可省略版本号
<build> 构建相关配置，包括插件、资源过滤等

💡 GAV 坐标：groupId + artifactId + version 三者组合唯一确定一个 Maven 构件。

5. 构建生命周期

⭐ Maven 提供三种主要的生命周期：Clean、Default、Site。每种生命周期包含多个阶段（phase），按顺序执行。

5.1 Clean 生命周期：项目清理

执行 Clean 生命周期，会删除 target 目录下的所有文件。

5.2 Default 生命周期：项目构建与部署

Default 生命周期是核心，包含编译、测试、打包、安装、部署等阶段：

阶段 命令 描述
validate mvn validate 验证项目是否正确且所有必须信息可用
compile mvn compile 编译源代码
test mvn test 使用单元测试框架（如 JUnit）运行测试
package mvn package 将编译后的代码打包成 JAR / WAR
verify mvn verify 对集成测试结果进行检查，保证质量达标
install mvn install 将包安装到本地仓库，供其他模块使用
deploy mvn deploy 将包部署到远程仓库，共享给其他开发人员

💡 执行某个阶段时，该阶段之前的所有阶段也会自动执行。例如 mvn package 会依次执行 validate → compile → test → package。

💡 可以组合多个生命周期的命令，例如 mvn clean package 先清理再打包。

5.3 Site 生命周期：生成项目站点

用于生成项目站点文档，包括项目报告、API 文档等。

5.4 常用插件命令

Maven 插件扩展了 Maven 的功能，可以完成一些特定任务：

命令 说明
mvn archetype:generate 创建一个新的 Maven 项目，生成项目骨架
mvn dependency:tree 查看项目依赖树
mvn dependency:analyze 分析项目依赖（未使用 / 未声明）
mvn dependency:resolve 解析项目依赖
mvn dependency:copy-dependencies 复制项目依赖到指定目录
mvn versions:display-dependency-updates 显示依赖的可用更新

6. 依赖管理

6.1 依赖范围

⭐ 通过 <scope> 标签指定依赖在不同阶段的有效范围：

依赖范围 编译 测试 运行时 说明
compile ✅ ✅ ✅ 默认范围，全程有效
provided ✅ ✅ ❌ 编译测试有效，运行时由容器提供（如 servlet-api）
runtime ❌ ✅ ✅ 测试运行时有效，编译时无效（如 JDBC 驱动）
test ❌ ✅ ❌ 仅测试时有效（如 JUnit）
system ✅ ✅ ❌ 类似 provided，需通过 <systemPath> 显式指定 jar 路径
import — — — 仅用于 <dependencyManagement>，导入外部 POM 的依赖管理配置

💡 import 范围的作用：在 dependencyManagement 中引入另一个 POM 的依赖管理，实现依赖版本的统一管理，常用于 Spring Boot 的 BOM（Bill of Materials）。

6.2 依赖传递性

🧠 Maven 会自动解决依赖的传递性。例如 A 依赖 B，B 依赖 C，那么 Maven 会自动将 C 也导入到 A 中。

传递性是否生效取决于依赖范围：

第一层依赖范围 是否传递 传递后的范围
compile ✅ 传递 compile
runtime ✅ 传递 runtime
provided ❌ 不传递 —
test ❌ 不传递 —

7. 总结与速记

7.1 Maven 核心知识点

维度 说明
定位 项目管理工具：依赖管理 + 构建管理 + 统一规范
核心概念 POM（项目对象模型），pom.xml 是核心配置文件
仓库 本地仓库 → 远程仓库（私服）→ 中央仓库
GAV 坐标 groupId + artifactId + version 唯一确定一个构件
三大生命周期 Clean（清理）、Default（构建部署）、Site（站点文档）
依赖范围 compile / provided / runtime / test / system / import
版本冲突规则 最短路径优先 → 先声明优先

7.4 易错点提醒

❌ mvn clean 属于 Clean 生命周期，mvn site 属于 Site 生命周期，不要混入 Default 生命周期的命令列表。

❌ <dependencyManagement> 只声明版本不实际引入依赖，<dependencies> 才会实际引入。

❌ <optional> 标记的依赖不会被传递，不是”可选是否引入”。

❌ 执行某个阶段时，该阶段之前的所有阶段都会自动执行，例如 mvn package 会先执行 compile 和 test。
