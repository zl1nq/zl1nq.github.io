一、AMQP 与 SpringAMQP

1. 什么是 AMQP

AMQP（Advanced Message Queuing Protocol） = 高级消息队列协议。

它是一套开放的、跨平台/跨语言的消息队列通信规范，定义了消息格式、交互流程、路由规则等标准。

只要都遵循 AMQP，Java 写的生产者可以发消息给 Python 写的消费者，平台语言无关，契合微服务的独立性要求。

2. 什么是 SpringAMQP

SpringAMQP 是 Spring 框架对 AMQP 协议的封装实现，提供了一套简洁的 API 模板来发送和接收消息。

它由两部分组成：

模块 作用
spring-amqp 基础抽象层，定义 API 规范和通用接口
spring-rabbit 具体实现层，基于 RabbitMQ 客户端实现上述 API

在 Spring Boot 项目中，我们只需要引入 spring-boot-starter-amqp 即可自动整合这两层，开箱即用。

第 3 步：提前在控制台创建目标队列

SpringAMQP 发消息时默认不会自动创建不存在的队列，如果目标队列不存在会报错。
建议先在 RabbitMQ 控制台（Queues 选项卡）把队列建好，或者用配置类声明 Queue Bean。

四、核心组件说明

1. RabbitTemplate

RabbitTemplate 是 SpringAMQP 提供的消息模板类，相当于 RabbitMQ 操作的门面。

常用方法 作用
convertAndSend(queue, msg) Simple 模式：直接投队列
convertAndSend(exchange, key, msg) 交换机模式：投交换机+路由键
receiveAndConvert(queue) 主动从队列拉取一条消息（不常用）

2. @RabbitListener

消费者端的核心注解，标记方法为消息监听器。

常用属性 作用
queues = {"q1", "q2"} 监听指定名称的队列（可多个）
bindings = @QueueBinding(...) 声明式创建「队列+交换机+绑定」（后续 Direct 章节详细讲）
ackMode 消息确认模式（AUTO/MANUAL/NONE，默认 AUTO）

3. 消息确认机制简述（Ack）

📌 初学者先理解默认行为即可：

默认 AUTO 模式：消费者方法正常返回 → 自动向 Broker 发 ACK；方法抛异常 → 不发 ACK，消息会被重新入队或丢弃（取决于配置）。

这样确保了「业务没处理成功，消息不会丢失」。

五、总结与速记

1. 整合三步速记

2. Simple 模型特点

特点 说明
路由方式 生产者→队列，跳过交换机
消息不丢失前提 队列已提前建好（不存在会报错）
消费者模式 推模式（Broker 主动推给消费者）
适用场景 学习、测试、最简单的一对一消费
生产环境不推荐原因 没有交换机，路由扩展能力差

3. 易错点提醒

❌ 把 port 写成 15672（控制台端口），连不上 RabbitMQ！

❌ 忘了加 @Component，@RabbitListener 完全不生效！

❌ 队列不存在就直接发消息，直接抛异常！

4. 记忆口诀

三步整合：引依赖，配连接，发收消息记心间。
Template 发，Listener 收，5672 端口别搞丢。
