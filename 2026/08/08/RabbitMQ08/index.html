一、MQ 可靠性概述

⭐ 消息到达 MQ 以后，如果 MQ 不能及时保存，也会导致消息丢失，所以 MQ 的可靠性也非常重要。

💡 前一篇解决了「发送者 → MQ」的可靠性（重试 + 确认），本篇聚焦「MQ 内部」的可靠性保障。

二、数据持久化

🔧 为了提升性能，默认情况下 MQ 的数据都是在内存存储的临时数据，重启后就会消失。为了保证数据的可靠性，必须配置数据持久化。

数据持久化包括三个方面：

持久化对象 作用
交换机持久化 Broker 重启后交换机仍然存在
队列持久化 Broker 重启后队列仍然存在
消息持久化 Broker 重启后消息不丢失

1. 交换机持久化

在控制台的 Exchanges 页面，添加交换机时可以配置 Durability 参数：

模式 说明
Durable 持久化模式（重启后存在）
Transient 临时模式（重启后消失）

2. 队列持久化

在控制台的 Queues 页面，添加队列时同样可以配置 Durability 参数。

⚠️ 重要澄清：队列持久化并不是把「分配给队列的内存」持久化下来，而是把队列的**元数据（结构信息）**持久化到磁盘，以保证 RabbitMQ Broker 重启后队列仍然存在。

队列中占用内存的本质内容其实是消息本身。惰性队列（Lazy Queue）控制的是消息在内存与磁盘之间的存放策略，而不是队列是否持久化。

3. 消息持久化

在控制台发送消息的时候，可以添加很多参数，而消息的持久化需要配置 properties 中的 delivery_mode。

4. 持久化 + 生产者确认

📌 关键机制：在开启持久化机制以后，如果同时还开启了生产者确认，那么 MQ 会在消息持久化以后才发送 ACK 回执，进一步确保消息的可靠性。

不过出于性能考虑，为了减少 IO 次数，发送到 MQ 的消息并不是逐条持久化到磁盘的，而是每隔一段时间批量持久化。这就会导致 ACK 有一定的延迟，因此建议生产者确认全部采用异步方式（publisher-confirm-type: correlated）。

5. Confirm 与 Return 的回执规则（结合持久化）

🧠 confirm 和 return 可以理解为两道防线，分别作用在「消息到达交换机」（confirm）和「交换机到达队列」（return）。

消息类型 成功条件 → 回执 失败条件 → 回执 路由失败
非持久化消息 入队成功 → ACK 未入队 → NACK 触发 Return
持久化消息 入队并持久化到磁盘 → ACK 持久化失败 → NACK 触发 Return

💡 持久化消息的 ACK 时机更晚（需等待磁盘写入完成），因此可靠性更高，但延迟也更大。

三、持久化 vs 非持久化：性能对比

1. 非持久化模式

💡 SpringAMQP 发送消息默认是持久化的，如果要发送非持久化的消息，要自定义构建器。

PageOut 行为：

  • page out：写出到磁盘
  • 当内存满时，会触发 page out 操作，将内存中的消息写入到磁盘中，以释放内存空间
  • 每一次 page out 操作都需要等待磁盘写入完成，MQ 会阻塞，这会导致性能下降

⚠️ 非持久化消息虽优先存内存，但内存满时仍会触发 PageOut 写入磁盘（而非直接丢弃），该过程阻塞队列进程。

2. 持久化模式

发送消息时直接持久化，每条消息都要写入磁盘，导致并发处理能力下降。

3. 吞吐曲线对比

模式 存储方式 吞吐曲线 原因
非持久化 优先内存，内存满时 PageOut 剧烈「波浪形」 纯内存操作极快，但内存满时 PageOut 阻塞导致骤降
持久化 直接写磁盘 「平滑稳定」 每条消息 IO 耗时形成天然缓冲，但并发能力下降

🧠 结论：非持久化模式因纯内存操作极快、缺乏缓冲，吞吐曲线剧烈波动；持久化模式因强制写入磁盘，IO 耗时形成天然缓冲，曲线更平滑稳定，但并发处理能力下降。

四、Lazy Queue：惰性队列

1. 背景：消息积压引发的 PageOut 阻塞

在默认情况下，RabbitMQ 会将接收到的消息保存在内存中以降低消息收发的延迟。但在某些特殊情况下，这会导致消息积压，比如：

  • 消费者宕机或出现网络故障
  • 消息发送量激增，超过了消费者处理速度
  • 消费者处理业务发生阻塞

一旦出现消息堆积问题，RabbitMQ 的内存占用就会越来越高，直到触发内存预警上限。此时 RabbitMQ 会将内存消息刷到磁盘上，这个行为称为 PageOut。

❌ PageOut 会耗费一段时间，并且会阻塞队列进程。在此过程中 RabbitMQ 不会再处理新的消息，生产者的所有请求都会被阻塞。

2. Lazy Queue 特征

为了解决这个问题，从 RabbitMQ 的 3.6.0 版本开始，增加了 Lazy Queues 模式，也就是惰性队列。惰性队列的特征如下：

特征 说明
直接落盘 接收到消息后直接存入磁盘而非内存
懒加载 消费者要消费消息时才会从磁盘中读取并加载到内存
大容量 支持数百万条的消息存储

💡 而在 3.12 版本之后，Lazy Queue 已经成为所有队列的默认格式。

4. 易错点提醒

❌ 队列持久化 ≠ 消息持久化：前者持久化队列元数据，后者持久化消息内容。

❌ 非持久化消息内存满时会触发 PageOut 写磁盘（阻塞），而非直接丢弃。

❌ 非持久化消息的 ACK 时机是「入队成功」，不是「到达交换机」。

❌ 参数名是 x-queue-mode（有 e），不是 x-queue-mod。

❌ Lazy Queue 控制的是消息存放策略，与队列是否持久化是两回事。
